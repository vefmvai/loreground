# /loreground:retro — разбор и починка

Пять шагов: найти сырьё → разобрать → показать → применить → записать отчёт.
Обоснования решений формы — в `reference.md` рядом. Читать, когда нужно объяснить
человеку, почему шаг устроен так, а не иначе.

**Предусловие:** запускать из **корня проекта агента**, чью сессию разбираем — история
сессий лежит по пути запуска, и архив отчётов должен лечь в тот же проект.

## Шаг 1. Найти стенограмму и оценить, есть ли о чём говорить

| Параметр | Default | Описание |
|---|---|---|
| `SESSION` | свежайшая стенограмма текущего проекта | id сессии или путь к `.jsonl` |

```bash
command -v jq >/dev/null || { echo "СТОП: нужен jq для разбора стенограммы."; exit 1; }
SLUG=$(pwd | sed 's/[^A-Za-z0-9]/-/g')
DIR="$HOME/.claude/projects/$SLUG"
# Разрешить SESSION: путь к .jsonl → как есть; id → $DIR/<id>.jsonl; пусто → свежайший
if   [ -f "$SESSION" ];                then F="$SESSION"
elif [ -n "$SESSION" ] && [ -f "$DIR/$SESSION.jsonl" ]; then F="$DIR/$SESSION.jsonl"
else F=$(ls -t "$DIR"/*.jsonl 2>/dev/null | head -1); fi
[ -f "$F" ] || { echo "СТОП: стенограмма не найдена ($DIR). Запущен из корня проекта агента?"; exit 1; }
SID=$(basename "$F" .jsonl | cut -c1-8)
```

Выжимка — реплики человека и текст агента с порядковыми номерами:

```bash
# Игнор ставится ПЕРЕД записью, а не после: ниже на диск лягут дословные цитаты сессии,
# и между их появлением и правилом игнора не должно быть ни одного шага. Один `git add .`
# в этом промежутке коммитит стенограмму целиком.
grep -qx '_retro/' .gitignore 2>/dev/null || printf '\n_retro/\n' >> .gitignore

mkdir -p _retro
# Код выхода jq проверяется отдельно от awk. В одном конвейере awk возвращает 0 даже
# когда jq упал: битая или обрезанная стенограмма даёт короткую выжимку с кодом 0, и
# гейт ниже читает её как «разбирать нечего». Это ровно «пустой вывод как доказательство».
jq -r '
  select(.type=="user" or .type=="assistant") | .type as $t | .message.content |
  if type=="string" then "=== \($t) ===\n\(.)"
  elif type=="array" then map(select(.type=="text")|.text)|select(length>0)|"=== \($t) ===\n\(join("\n"))"
  else empty end' "$F" > _retro/_raw.txt \
  || { echo "СТОП: стенограмма не разобралась (jq код $?). Это НЕ «разбирать нечего» — разбор не состоялся."; exit 1; }
awk '/^=== (user|assistant) ===$/{n++; sub(/ ===$/, " #" n " ===")} {print}' _retro/_raw.txt > _retro/_digest.md
rm -f _retro/_raw.txt
wc -l _retro/_digest.md; grep -c '^=== user' _retro/_digest.md
```

**Гейт:** реплик человека меньше двух и содержательной работы нет → сказать «разбирать
нечего» и остановиться. Находки ради процесса не выдумываются. **«Разбирать нечего» и
«разбор не состоялся» — разные ответы:** первый говорится только после успешного разбора,
второй хук выше выдаёт сам.

**Приватность:** `_retro/` держит дословные цитаты сессии — возможны адреса, домены,
ключи. Правило игнора ставит команда выше, до первой записи; заготовка целиком —
`standard/gitignore.example`.

## Шаг 2. Разбор свежим проверяющим

Запустить субагента типом `general-purpose`. **Инструмент зовётся `Agent` или `Task` —
имя зависит от версии среды**, поэтому в `allowed-tools` объявлены оба: скилл, назвавший
только одно имя, в другой среде молча не выполнит этот шаг. Бери то, что есть.
Передать **путь** к выжимке, не её содержимое. Промпт — целиком:

> Ты — внешний ревизор сессии ИИ-агента. Задача — найти, что стоит забрать в память
> и в правила агента, а не оправдать сделанное. Прочитай `_retro/_digest.md`.
> Железные правила:
> 1. Каждая находка привязана к моменту стенограммы (номер реплики + короткая цитата).
>    Без привязки — выбрасывай.
> 2. Пиши обезличенно: без адресов, доменов, ключей, имён людей и прочих частностей
>    работы. Находка описывает **поведение агента**, а не содержание задачи.
> 3. Фильтр значимости: только то, что повлияло на исход или повторится. Косметику
>    сведи в одну строку. Нет значимого — так и скажи.
> 4. Если в конце сессии агент сам вынес хвосты («Попутно замечено», «Усвоенные
>    уроки», предложения записать в память) — пройди по каждому пункту отдельно и
>    реши его судьбу явно. Особо проверь: не ошибся ли агент в причине — урок «по
>    горячим следам» часто фиксирует неверный корень; сверь с дальнейшим ходом сессии.
> 5. Загляни в прошлые отчёты `my/retro/*.md`, если они есть. Находка, встречавшаяся
>    там же, помечается «повторяется, N-й раз» — это меняет её вес.
> 6. Для каждой находки предложи маршрут по таблице:
>    - факт предметной области → память агента: знание (накапливать, с источником) /
>      состояние (перезапись в каноническом доме + пересборка производных) / журнал («почему»);
>    - косяк в правилах, навыках или персоне самого агента → правка этих файлов;
>    - дефект внешней системы (скрипт, сервис, конфиг — не агент и не его память) →
>      починить прямо сейчас, в память не записывать;
>    - урок, верный ЛЮБОМУ агенту (тест: «верно для агента, который об этой конкретной
>      установке не слышал?») → предложение автору стандарта.
> Верни markdown: вердикт (2–3 фразы) · что сработало (1–3 пункта) · находки
> (момент, суть, корень, маршрут, предлагаемая правка).

## Шаг 3. Показать человеку и спросить

1. Показать короткий отчёт: вердикт, находки одной строкой с маршрутами.
2. По каждой находке спросить решение: **применить / отложить / отбросить.**

Без этого ответа дальше не идти. Автоматическая правка памяти ошибается тихо, и цена
ошибки выше цены одного вопроса.

## Шаг 4. Применить подтверждённое

**Маршрут решает, ГДЕ живёт результат, а не КОГДА делается работа.** Всё подтверждённое,
что выполнимо сейчас, делается сейчас — включая починку внешних систем, если доступ есть.
Откладывание — исключение с названной причиной, не способ закрыть находку.

По закону модуля-адресата:

- **Знание** → заметка по шаблону стандарта, с провенансом «сессия `<id>`, момент #N».
- **Состояние** → перезапись в каноническом доме (+ дата, + пересборка потребителей
  из паспорта состояния).
- **Журнал** → запись «почему» с датой.
- **Правила и навыки агента** → правка его файлов. Это и есть починка: то, из-за чего
  агент ошибся, чинится в том файле, который его этому научил.
- **Внешняя система** → починить; если сейчас нельзя (нет доступа, другая машина) —
  задача в бэклог агента с причиной.
- **Предложение автору стандарта** → issue или сообщение, с датой и ссылкой на сессию,
  обезличенно. Слой автора у пользователя read-only (стандарт § 9.4) — правкой ядра
  предложение не оформляется никогда.

**После правок памяти — прогнать валидатор** (`lore-validate` или `standard/validate.py`).
Незелёный результат означает, что работа не закончена, а не «потом поправим».

## Шаг 5. Записать отчёт в архив

```bash
# Имя агента — из метки, если она есть; иначе имя папки. Пустой результат метки
# не годится: он даёт файл без имени и молча ломает сортировку архива.
NAME=$( [ -f .loreground ] && grep -m1 '^имя:' .loreground | sed 's/^имя: *//; s/ *$//' )
[ -n "$NAME" ] || NAME=$(basename "$PWD")
mkdir -p my/retro
# → my/retro/2026-07-29-sysadmin-retro-a1b2c3d4.md
echo "my/retro/$(date +%F)-$NAME-retro-$SID.md"
```

В отчёт: вердикт, находки, принятое по каждой решение, что применено. **Обезличенно —
без адресов, доменов, ключей, путей вида `/home/имя`, почты:** отчёт когда-нибудь
покажут человеку. От git архив спрятан по умолчанию (`gitignore.example`), отправка —
отдельное действие. Выжимка `_retro/` остаётся локальной и не коммитится никогда.

**Дописав отчёт — прогони проверку обезличенности, не полагайся на то, что писал
аккуратно:**

```bash
lore-validate --check-anon my/retro   # 0 — частностей нет · 1 — найдены · 2 — нечего проверять
```

Нашла — правь отчёт, а не глуши проверку. Она смотрит образцы (адреса, ключи, почту,
домашние пути), а не смысл: зелёный прогон значит «известных форм нет», а не «утечки
нет». Пересказанный секрет она пропустит, поэтому обезличенно пишется сразу.

Архив нужен не только для истории: следующий разбор читает его и видит, что беда
всплывает не в первый раз.

## Подводные камни

- **Разбор своей же сессии льстит** — проверяющего не сворачивать ради скорости, судит он.
- **Не раздувать**: тридцать находок за сессию — разбор умрёт на третьем запуске.
- **Хвосты сессии не растворять**: каждый пункт «Попутно замечено» получает явную судьбу.
- **Починка правил — не переписывание персоны.** Правится то, что назвала находка, и только оно.
