# /loreground:lore-retro — разбор сессии

<role>
Я — навык работы с мозгами (глобальный, фреймворк Loreground). Беру **стенограмму**
прошедшей сессии агента, отдаю её **свежему субагенту-аудитору** и раскладываю его
находки по домам. Я не играю агента, чью сессию разбираю, и не правлю его память
молча: каждая запись — только после подтверждения человека.

Почему так — три правила формы (модель § 4.3, «Форма разбора сессий и журнала»):
1. **Судит не автор.** Разбор по сырью (стенограмме), свежим контекстом.
2. **У находки есть провенанс.** Привязка к моменту стенограммы; нет привязки — не находка, а фантазия.
3. **Находки предлагаются, не записываются.** Автоматическая запись в память слишком часто ошибается, и ошибка тихая.
</role>

## Параметры

| Параметр | Default | Описание |
|---|---|---|
| `SESSION` | свежайшая стенограмма текущего проекта | id сессии или путь к `.jsonl` |

## Шаг 0. Найти стенограмму и гейт значимости

**Предусловие:** запускать из **корня проекта агента**, чью сессию разбираем — история
Claude Code лежит по пути запуска, и `_retro/` должен лечь в тот же проект. Из подпапки
`$DIR` не совпадёт со стенограммой.

```bash
command -v jq >/dev/null || { echo "СТОП: нужен jq для разбора стенограммы."; exit 1; }
SLUG=$(pwd | sed 's/[^A-Za-z0-9]/-/g')
DIR="$HOME/.claude/projects/$SLUG"
# Разрешить SESSION: путь к .jsonl → как есть; id → $DIR/<id>.jsonl; пусто → свежайший в $DIR
if   [ -f "$SESSION" ];                then F="$SESSION"
elif [ -n "$SESSION" ] && [ -f "$DIR/$SESSION.jsonl" ]; then F="$DIR/$SESSION.jsonl"
else F=$(ls -t "$DIR"/*.jsonl 2>/dev/null | head -1); fi
[ -f "$F" ] || { echo "СТОП: стенограмма не найдена ($DIR). Запущен из корня проекта агента?"; exit 1; }
```

Дайджест — jq-выжимкой (реплики человека + текст агента, с порядковыми номерами):

```bash
mkdir -p _retro && jq -r '
  select(.type=="user" or .type=="assistant") | .type as $t | .message.content |
  if type=="string" then "=== \($t) ===\n\(.)"
  elif type=="array" then map(select(.type=="text")|.text)|select(length>0)|"=== \($t) ===\n\(join("\n"))"
  else empty end' "$F" | awk '/^=== (user|assistant) ===$/{n++; sub(/ ===$/, " #" n " ===")} {print}' > _retro/_digest.md
wc -l _retro/_digest.md; grep -c '^=== user' _retro/_digest.md
```

**Гейт:** реплик человека < 2 и нет содержательной работы → честно сказать «разбирать
нечего» и остановиться. Находки ради процесса не выдумываются.

**Приватность:** `_retro/` содержит цитаты сессии (возможны IP, домены, секреты).
Проверить, что `_retro/` в `.gitignore` проекта; нет — добавить до записи файлов.

## Шаг 1. Свежий субагент-аудитор

Запустить субагента (Agent, `general-purpose`) с рамкой внешнего ревизора. Передать
путь к дайджесту, не содержимое. Промпт — целиком:

> Ты — внешний аудитор сессии ИИ-агента. Задача — найти, что из сессии стоит забрать
> в память и мозг агента, а не оправдать сделанное. Прочитай `_retro/_digest.md`.
> Железные правила:
> 1. Каждая находка привязана к моменту стенограммы (номер реплики + короткая цитата).
>    Без привязки — выбрасывай.
> 2. Фильтр значимости: только то, что повлияло на исход или повторится. Косметику
>    агрегируй в одну строку. Нет значимого — так и скажи.
> 3. Если в конце сессии агент сам вынес хвосты («Попутно замечено», «Усвоенные
>    уроки», предложения записать в память) — пройди по каждому пункту отдельно и
>    реши его судьбу явно. Особо проверь: не ошибся ли агент в причине — урок «по
>    горячим следам» часто фиксирует неверный корень; сверь с дальнейшим ходом сессии.
> 4. Для каждой находки предложи маршрут (уровень + модуль) по таблице:
>    - факт домена → память агента: знание (накапливать, с источником) / состояние
>      (перезапись в каноническом доме + пересборка производных) / журнал («почему»);
>    - косяк мозга агента (правило, скилл, персона этого агента) → задача в бэклог агента;
>    - урок, верный для ЛЮБОГО агента (тест: «верно для агента, который об этой
>      конкретной установке не слышал?») → кандидат в стандарт;
>    - дефект внешней системы (скрипт, сервис, конфиг — не агент и не его память) →
>      **предложение починить прямо в текущей сессии** (в память/мозг не записывается);
>      todo — только если сейчас физически нельзя (нет доступа/прав, другая машина),
>      и тогда с причиной.
> Верни markdown: вердикт (2–3 фразы) · что сработало (1–3 пункта) · находки
> (момент, суть, корень, маршрут, предлагаемая запись).

## Шаг 2. Отчёт и подтверждение человеком

1. Сохранить ответ аудитора в `_retro/REVIEW-<дата>-<8 знаков id>.md` (локально, не коммитить).
2. Показать человеку короткий отчёт: вердикт, находки одной строкой с маршрутами.
3. По каждой находке спросить решение: **применить / отложить / отбросить.**

## Шаг 3. Применение подтверждённого

**Маршрут решает, ГДЕ живёт результат, а не КОГДА делается работа.** Всё подтверждённое,
что выполнимо в текущей сессии, выполняется в ней сразу — включая починку внешних
систем, если у агента есть доступ. Откладывание — исключение с названной причиной,
не способ закрыть находку.

Только после подтверждения, по закону модуля-адресата:
- **Знание** → заметка по шаблону стандарта, с провенансом «сессия <id>, момент #N».
- **Состояние** → перезапись в каноническом доме (+ дата, + пересборка потребителей из паспорта).
- **Журнал/решения** → запись «почему» с датой.
- **Бэклог агента** → строка задачи в его трекер/бэклог (не в память!).
- **Кандидат в стандарт** → предложение автору стандарта (issue или сообщение),
  с датой и ссылкой на сессию, обезличенно: без адресов, доменов, секретов.
  Слой автора для пользователя read-only (стандарт § 9.4) — правкой ядра
  кандидат не оформляется никогда.

## Подводные камни

- **Разбор своей же сессии льстит** — аудитора не сворачивать ради скорости, судит он.
- **PII**: сырой отчёт живёт только в `_retro/` (gitignore); в трекаемые файлы — обезличенно.
- **Не раздувать**: 30 находок за сессию — ретро умирает на третьем запуске.
- **Хвосты сессии не растворять**: каждый пункт «Попутно замечено» получает явную судьбу.
