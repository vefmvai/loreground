# Loreground

**Стандарт памяти для ИИ-агента — со слоем доверия к фактам.**

Проект русскоязычный: стандарт, сообщения валидатора и шаблоны — на русском.

> ⚠️ **0.30.0 — у суждения появился дом: назови его автора.**
>
> В стандарте были факт («проверяется снаружи» → `knowledge` + источник) и наблюдение
> («ты это видел» → `source` с `source_type: personal-experience`). Третьего случая —
> **утверждения, которое проверить снаружи нельзя по устройству**, — не было, и такие
> заметки молча ложились в `concept`, где провенанс не спрашивается вовсе.
>
> Отдельного типа для них **не заведено намеренно**. Живая база показала, что задача
> решается не типом: суждение, названное чьим-то, снова проверяемо — вопрос меняется
> с «правда ли это» на «правда ли он так считает», а второе проверяется обычным
> провенансом. Поэтому § 2.1 получил правило: **суждение называет, чьё оно.** Автор
> становится заметкой-источником с оценкой надёжности; если автор — ты сам, механизм
> уже есть (`source_type: personal-experience`), и один корень не даёт `confirmed` —
> одно мнение остаётся одним мнением, сколько бы заметок его ни повторяло.
>
> **Сказано и то, чего нет:** безымянное суждение — единственное, чему дома в этой
> модели не нашлось, и **машины под правило не будет** (валидатор видит поля, а не
> смысл). Обе оговорки стоят в тексте, а не подразумеваются.
>
> **Что дописать в конфиг:** ничего. **Что сделать с базой:** если у тебя есть заметки
> с оценками и выводами — проверь, названо ли, чьи они.

## Что это

Разложить знания агента по markdown-файлам с YAML-frontmatter умеют многие. Loreground добавляет то, чего обычно нет, — **доверие к записанному**:

- **Провенанс.** У каждого знания есть заметка-источник. Знание без источника — неполноценное.
- **Вычисляемый консенсус.** Метка «подтверждено» ставится не на глаз, а по числу **независимых корней**: пересказ, перевод и обзор корня не создают. Считает машина.
- **Запрет выдуманных источников.** «Эксперт сказал, что есть исследование» — не доказательство. Источник либо реально найден, либо факт помечен непроверенным.
- **Знания со сроком годности.** Что протухает — помечено, и агент это оговаривает.
- **Один дом у факта.** Значение живёт в одной заметке; обновление — перезапись на месте, а не вторая запись рядом.

| Шаблоны заметок | `standard/templates/` | знание, источник, индекс |
| Развернуть память агента | `/loreground:init` | работает: новый агент и подключение к готовому |
| Разбор сессии с починкой | `/loreground:retro` | работает |
| Стартовая загрузка по паспорту | `hooks/startup-load.py` | работает: что объявлено `by: hook` — приезжает всегда, вес меряется, потолок сторожится |
| Сторож свежести кодекса | `hooks/codex-freshness.py` | работает: молчит, пока копия кодекса в правилах совпадает с источником по версии и текст блока на месте |
| Сторож расхождения версий | `hooks/version-drift.py` | работает: называет вслух, когда комплект ушёл вперёд, а агент собран на прошлой версии |
| Автопрогон валидатора | `hooks/validate-on-write.py` | работает: после записи в базу отчёт приезжает сам; зелёный молчит |
| Обновление собранного агента | `core.md` § 9.3.1 | процедура, а не навык: шесть шагов с ветвлением по режиму. Что не трогается при обновлении и почему порядок шагов не переставляется — сказано там же |
| Навык ввода знания | — | **не написан**: пока по процедуре `core.md` § 11 и шаблонам |
| Навык ревизии памяти | — | **не написан**: часть работы делает `/loreground:retro` |

## Установка

Магазин добавляется один раз, дальше ставится сам плагин:

```
/plugin marketplace add vefmvai/claude-plugins
/plugin install loreground@vefmvai
/reload-plugins
```

**Если этих команд у тебя нет** (в расширении для VS Code подсказка отвечает «No matching
commands») — то же самое делается из терминала, и это не обходной путь, а равноценный:

```
claude plugin marketplace add vefmvai/claude-plugins
claude plugin install loreground@vefmvai
```

**После установки сессию нужно перезапустить, и только потом звать `/loreground:init`.**
В уже открытой сессии навыки свежепоставленного комплекта не появляются — команда
ответит, что такой нет. Сказано отдельно, потому что «поставил — и сразу разворачивай»
выглядит естественным порядком, а перезапуск стоит контекста разговора: лучше знать о нём
до того, как соберёшь в сессии что-то ценное.

Посмотреть, ничего не устанавливая:

```
git clone https://github.com/vefmvai/loreground.git
claude --plugin-dir ./loreground
```

Обновление — `/plugin update loreground@vefmvai`, и **оно требует перезапуска**: до него
команда `lore-validate` продолжает вести в старую версию, молча. Проверить, что приехало:

```
claude plugin list          # версия установленного комплекта
```

**Только этой строкой и проверяется.** Прежде здесь стоял ещё `lore-validate --help` —
он для этого не годится: справка через три релиза подряд даёт байт в байт тот же вывод,
и отличить «приехало» от «не приехало» им нельзя. Рецепт, который всегда выглядит
одинаково, проверкой не является.

**Если ядро разложено копией — этой строки мало.** `claude plugin list` показывает версию
комплекта, а твой стандарт лежит у тебя и обновляется **отдельной процедурой**
(`standard/core.md` § 9.3.1). Совпадение номера комплекта ничего не говорит о твоей копии.

**Первый шаг после установки — `/loreground:init`.** Навык проводит по развёртыванию
целиком: правила агента, `config.yaml`, метка `.loreground`, начальный индекс. Он же
нужен, чтобы заработали хуки ниже, — без метки они молчат.

Хочешь сначала потрогать, не разворачивая агента — бери **три** шаблона, а не два:

```
mkdir proba
cp standard/templates/00-index.md proba/              # ← без него прогон красный
cp standard/templates/knowledge.md  "proba/Кофеин.md"
cp standard/templates/source.md     "proba/Обзор 2025.md"
# заполни угловые скобки, включая created (сегодняшняя дата), и свяжи ссылками:
# индекс → Кофеин → Обзор 2025
lore-validate proba
```

**Почему индекс обязателен, а не «желателен».** База — это граф с одной точкой входа
(`§ 7.2`): без `00-index.md` валидатор даёт две ошибки — «нет Home-индекса» и «сироты», —
и обе **не про качество твоих заметок**, а про то, чего тебе не сказали создать. Позвать
написать две заметки и прогнать — рецепт безупречный, а результат гарантированно красный
экран на первом знакомстве с продуктом, у которого «зелёный молчит». Связать ссылками нужно по той же причине: заметка без входящих
`[[ссылок]]` — сирота, даже если она идеальна.

Так видно форму записи, но ни хуков, ни кодекса в правилах при этом нет.

**Сам стандарт — `standard/core.md`.** Это основной текст, а не приложение: шаблоны и
сообщения валидатора отсылают к его разделам (`§ 4.2` — словарь источников, `§ 11` —
порядок ввода знания). README рассказывает, что это и как поставить; как этим
пользоваться — там.

### Что плагин запускает сам

Комплект ставит **четыре хука** — команды, которые Claude Code выполняет сам: три при старте сессии, одну после записи файла. Пятый файл в папке хуком не является: это их общий ответ на собственную поломку.
Это сказано здесь, а не мелким шрифтом: плагин, запускающий что-то на твоей машине, обязан
объявить это первым.

| Хук | Строк | Что делает |
|---|---|---|
| `hooks/startup-load.py` | 155 | кладёт в контекст то, что твой `config.yaml` объявил строками `by: hook` — паспорт стартовой загрузки (§ 6.3) |
| `hooks/codex-freshness.py` | 221 | сверяет **номер версии** кодекса в твоих правилах и присутствие текста блока; правку внутри блока не увидит |
| `hooks/version-drift.py` | 171 | сверяет версию сборки из метки `.loreground` с версией комплекта на машине |
| `hooks/validate-on-write.py` | 213 | после записи `.md` в базу прогоняет валидатор **командой из твоего `config.yaml`** и показывает отчёт, если он не зелёный |
| `hooks/_broken.py` | 41 | не хук: общий ответ всех четырёх на **собственную** поломку. Дом один, чтобы четыре копии одного текста не разошлись |
| `hooks/_out.py` | 41 | не хук: единственная печать строки в контекст. Дом один, потому что вместе с печатью копировалось решение о кодировке — и неверным оказалось сразу во всех копиях |

Все четыре живут по одним правилам:

- **Работают только там, где лежит `.loreground`** — метка, которую кладёт `/loreground:init`.
  В остальных проектах не делают ничего и ничего не читают.
- **Автопрогон молчит, если в твоём `config.yaml` нет строки `command`** — своей команды
  он не придумывает (иначе проверял бы не тем, чем ты проверяешь руками). Навык сборки
  эту строку пишет всегда; но если ты собирал агента сам, тишина после записи означает
  не «чисто», а «нечем прогонять».
- **Сами ничего не пишут в твои файлы и в сеть не ходят.** Три из четырёх только читают. Четвёртый, автопрогон валидатора, **запускает внешний процесс** — ровно ту команду, которую ты сам записал в свой `config.yaml`, и ничего кроме неё. Это сказано отдельной строкой, потому что «только читают» про него было бы неправдой. Загрузчик читает
  **только внутри твоего проекта**: путь с `..`, абсолютный путь и символьную ссылку наружу
  он отвергает и говорит об этом. Проверяется разрешённый путь целиком, а не его папка.
- **Молчат, когда нечего сказать.** Ни строки в контекст — стартовая загрузка оплачивается
  каждой сессией.
- **«Не смог» и «всё в порядке» — разные ответы.** Объявленный файл не найден, паспорт не
  разобрался, источник кодекса не нашёлся, в конфиге нет команды прогона — об этом будет
  сказано, а не промолчано. Список закрытый: он перечисляет то, о чём хуки говорят, а не
  обещает, что молчание в остальных случаях всегда значит «чисто».

**Зачем это нужно.** Строка в правилах «при старте прочитай то-то» — просьба: она сработает,
если модель не отвлеклась. Хук — не просьба. Что объявлено в паспорте как `by: hook`, то
приезжает всегда, и это единственный способ выполнить требование § 6.3 п. 2.

Не нужны — выключаются штатно: `/plugin disable loreground@vefmvai` снимает весь комплект,
либо удали `hooks/hooks.json` из своей копии.

### Что нужно на машине

| Зависимость | Зачем | Без неё |
|---|---|---|
| **Python 3** | валидатор базы **и все четыре хука** | валидатор не запускается; хуки не запускаются тоже — а они молчат и когда им нечего сказать, поэтому их отказ заметить труднее всего. **На Windows читай абзац ниже: там Python бывает установлен, а комплект его не находит** |
| **PyYAML** | валидатор базы, стартовая загрузка, автопрогон | валидатор не запускается: большинство проверок опирается на разбор frontmatter, а частичный прогон внешне неотличим от чистого. Хуки об этом говорят вслух. **Ставить не «куда-нибудь», а в нужный интерпретатор** — если Python на машине не один, читай раздел ниже; команду с полным путём печатают сами инструменты |
| **bash** | команда `lore-validate` **и шаги обоих навыков** — сборки и разбора: они подставляют дату, правят файлы и страхуются проверками через `date`, `sed`, `grep` | `env: bash: No such file or directory`. Сам валидатор при этом цел: `python3 <папка плагина>/standard/validate.py` работает без bash. А вот навыки без него встанут посреди процедуры — и, например, в новую заметку уедет незаменённый плейсхолдер `created: <…>` вместо сегодняшней даты |
| **jq** | навык разбора сессий `/loreground:retro` | навык останавливается на первом шаге и говорит об этом |

Пока плагин включён, команда **`lore-validate`** доступна агенту в любой папке — это тот же валидатор. В своём терминале запускай его по пути: `python3 <папка плагина>/standard/validate.py`. Слово `python3` здесь значит «тот Python, который у тебя первый в PATH» — если их несколько, читай следующий раздел.

### Если Python на машине не один

Обычное дело на macOS с Homebrew: рядом живут системный Python и поставленный из
Homebrew. Слово `python3` тогда значит **разное в разных местах**, и `pip install pyyaml`
кладёт библиотеку в один интерпретатор, пока прогон идёт другим. Снаружи это выглядит
как «поставил, а он всё равно не видит».

PyYAML нужен **двум разным запускам**, и это не одно и то же:

| Кому | Каким интерпретатором | Можно ли выбрать |
|---|---|---|
| Хукам комплекта | `python3` — так они объявлены в `hooks/hooks.json` | **нет.** Строка зашита в комплект и настройке не поддаётся |
| Прогону валидатора | тем, что стоит первым словом в `validate.command` твоего `config.yaml` | **да**, вплоть до полного пути |

Отсюда правило: **PyYAML обязан стоять в том Python, который в PATH первым** — иначе хуки
мертвы, а `config.yaml` этого не лечит. Узнать, что это за интерпретатор:

```bash
python3 -c "import sys; print(sys.executable)"
```

Спрашивать не обязательно: и валидатор, и хуки печатают **готовую команду с полным
путём**, когда библиотеки не находят, — тот, кто говорит, и есть тот, кому её ставить.

**В `validate.command` полный путь разрешён:** `/usr/bin/python3 standard/validate.py
knowledge --core standard` — законная команда. Требование § 9.3 п. 7 (в конфиге та же
команда, что зовёшь руками) при этом выполнимо: рукой набирай ту же строку целиком.

**Если Homebrew-Python отказывается ставить в себя** (`externally-managed-environment`,
PEP 668) — это его защита от смешивания с системными пакетами, а не поломка. Тогда либо
ставь с `--break-system-packages`, либо оставь хукам тот интерпретатор, куда PyYAML
поставился. Отдельное виртуальное окружение задачу решает только наполовину: прогон в него
увести можно строкой `validate.command`, а хуки — нет, они всё равно позовут `python3`.

### Windows

Одна особенность, которая выглядит как «всё в порядке», и потому названа отдельно.

**Команда `python3` на Windows есть не всегда — она зависит от способа установки.** А
комплект зовёт интерпретатор именно так: четыре хука в `hooks/hooks.json`, команда
`lore-validate`, шаги обоих навыков и та команда прогона, которую навык сборки запишет
в твой `config.yaml`.

Как расходятся способы установки:

| Как поставлен Python | Есть ли `python3` |
|---|---|
| Классический установщик с python.org | **нет** — в PATH кладутся `python.exe` и лаунчер `py.exe` |
| Python Install Manager (нынешний способ с python.org) | есть; документация Python называет его «not meant to be widely used or recommended» |
| Из Microsoft Store | есть |
| Чистая Windows без Python | «есть» ложно: алиас `python3.exe` из `WindowsApps` перекидывает в магазин |

Отсюда два следствия, оба неочевидные:

- **Ответ `python3 --version` читать надо внимательно.** «Не является внутренней или
  внешней командой» и предложение открыть Microsoft Store — оба означают «команды нет»,
  хотя выглядят по-разному. А на машине с классическим установщиком первый ответ придёт
  при **установленном и работающем** Python.
- **Хуки при этом молчат.** Не найдя команду, они просто не выполняются, а их молчание по
  устройству комплекта означает «мне нечего сказать». Агент выглядит оснащённым четырьмя
  сторожами, которых нет: ни паспорта загрузки, ни сверки версий, ни автопрогона после
  записи.

Если команды нет — лечится копией интерпретатора рядом с оригиналом, в той же папке, где
лежит `python.exe`:

```powershell
Copy-Item "$PythonDir\python.exe" "$PythonDir\python3.exe"
```

Проверить, что помогло: `python3 --version` отвечает номером версии. Если вместо этого
открылся магазин — впереди в PATH стоит алиас из `WindowsApps`, его нужно отключить
(«Параметры» → «Псевдонимы выполнения приложения»).

**Отчёт валидатора на консоли не в UTF-8.** Прогон не упадёт, но значки `✅` и `❌`
станут одинаковым `?` — консоль в cp1251 их не умеет. Русский текст при этом читается,
и вердикт каждой строки виден по словам: «Битых ссылок нет» против «БИТЫЕ ССЫЛКИ (3)».
Итог прогона — по последней строке и по коду выхода, а не по значку.

**Оболочка.** Шаги обоих навыков написаны на bash (см. таблицу выше). На Windows их
выполняет Git Bash — если его нет, навыки встанут посреди процедуры.

## Честные границы

Проект обязан говорить о себе то же, что требует от чужих баз.

- **Модель памяти — рабочая конструкция, а не доказанная теория.** Она устроена так, чтобы её можно было включать по частям: берите то, что нужно вашему агенту.
- **Переносится модель, а не инструменты** — если память агента лежит в базе данных, а не в файлах. Что именно переносится, что придётся заменить своими средствами и в каком порядке переезжать — `core.md` § 0, врезка «А если моя память не в файлах». Здесь указатель, а не пересказ: у этого вывода один дом, и раньше он был написан в двух местах независимо.
- **Зелёный валидатор не значит «база здорова».** Он проверяет, что заявленное непротиворечиво, и никогда — что за заявленным что-то есть. Полный список того, чего `exit 0` не значит, — `core.md` § 10.1.
- **Подключение существующей базы — работа, а не импорт.** Разложить пару сотен заметок по стандарту — это дни, и почти всё в них — суждения человека, а не механика.
- **«Покажи откуда» — не «покажи публикацию».** Слой доверия сделан на домене, где источники формальны (исследования, документация), и в домене без них читается как требование, которого не выполнить. Это недоразумение: словарь `source_type` (`core.md` § 4.2) прямо содержит собственный опыт, практика и веб-страницу, у каждого свой базовый уровень доверия. **Источник — это ответ на «откуда я это знаю», а не ссылка на журнал.** Разговор с мастером, свой прогон, страница в блоге — законные источники; нечестен не слабый источник, а **невыясненный**. Чего слой доверия не переживает — так это заметки, у которой ответа нет вовсе, и заметки, где ответ придуман задним числом.
- **Прогоняется на macOS. С Windows есть отчёт пользователя, с Linux — нет.** Сказано
  прямо, потому что «не проверяли» и «работает» — разные вещи, а молчание читается как
  второе. **Что дал отчёт с Windows 10 (сборка 19045, Git Bash + PowerShell):** три
  поломки, все молчаливые, и все три починены в 0.27.0 — раздел «Windows» выше и врезка
  наверху. Проверить их на Windows своими руками мы не можем: машины нет, и правки писаны
  по коду. Что известно помимо этого: валидатор и хуки — обычный Python 3 без системных
  вызовов, файлы с виндовыми переносами строк (CRLF) прогоняются штатно; команда
  `lore-validate` требует `bash`, и без него нужен прямой вызов
  `python3 <папка плагина>/standard/validate.py`. Навык разбора сессий опирается на `jq`
  и оболочку. Если проверишь у себя — расскажи, что сломалось.
- **Хук, который сломался, скажет об этом.** Раньше все четыре молчали о собственной поломке — «не смог» выглядело как «всё в порядке». Теперь при своей ошибке хук кладёт в контекст одну строку: что сломалось и как прогнать его руками. Сессию он по-прежнему не роняет. **Шумит только сломанный**; если тебе это не нужно — выключи хук в настройках, это твоё решение, а не наше за тебя.
- **Прогон целиком, инкрементального нет.** После правки одной заметки проверяется вся база: 10 000 заметок ≈ 9 с, 50 000 ≈ 47 с — измерено. На порядке десяти тысяч это рабочий инструмент, дальше прогон после каждого ввода знания (`core.md` § 11 п. 12) станет заметным. Отчёт при этом нечем ограничить и нечем обработать: ни лимита ошибок, ни машинного формата — на большой базе это мегабайт текста в терминал.
- **У плоской базы есть потолок, и он близко.** Home-индекс ограничен 25 КБ (`--index-limit-kb`, `core.md` § 7.2), потому что читается в каждой сессии. Это 25 600 Б ÷ 80–120 Б на строку ≈ **210–320 заметок**, дальше индекс придётся разбирать на MOC. Не авария, но работа, и она наступит.

## Куда присылать находки

Проект сырой и открытый, и обратная связь мне нужна по-настоящему. Адрес один — **[issues репозитория](https://github.com/vefmvai/loreground/issues/new/choose)**, там две формы.

**«Не заработало»** — поломка, непонятная формулировка, отвалилось на другой системе. Форма спросит версию, систему и что стоит на машине.

**«Находка про стандарт»** — самое ценное. Это находка из `/loreground:retro` с маршрутом «предложение автору стандарта»; у него проверочный вопрос: *верно ли это для агента, который про эту установку вообще не слышал?* Форма спрашивает версию комплекта, режим подключения и слой доверия — **без них находку нечем воспроизвести**, и она превращается в анекдот. Собирать это руками не надо, скажи агенту:

> Оформи предложение автору стандарта по моим разборам: собери находки с этим маршрутом, приложи версию и режим из метки, проверь обезличенность и покажи мне готовый текст.

Он соберёт, обезличит и покажет. Отправит — только по твоему «да».

**Отдельное поле формы — твой `config.yaml`, и оно важнее, чем выглядит.** По нему видно, какими частями стандарта ты пользуешься, а какими нет. Это самая честная обратная связь, какая бывает: где правило оказалось слишком дорогим, там его выключили, и никакой текст этого не расскажет. Личного в конфиге нет — объявленные типы, паспорт стартовой загрузки и команда прогона.

**Ничего не уходит само.** Телеметрии в комплекте нет: ни строчки, ни разу, ни в каком виде. Отправка — всегда явное действие человека, и это не забывчивость, а решение (§ 1.1).

Pull request тоже приму, если умеешь и хочешь. Но полезнее **наблюдение, чем патч**: формулировку правила и обоснование к ней пишу я, а увидеть то, чего не видит мой агент, можно только через твой.
